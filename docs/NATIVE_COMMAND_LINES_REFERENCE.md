# Native command feedback visibility

The supplied RA2 executable has a shared **25-logic-frame** action-line timer. This is static evidence from the same binary whose provenance and SHA are recorded in [the speed reference](NATIVE_SPEED_REFERENCE.md), not a wall-clock measurement of an unmodified retail release. Relevant instructions are preserved in [the disassembly excerpt](../tests/artifacts/gameplay/native-command-lines-disassembly.txt).

The Unit constructor sets its primary vtable to `0x7addf8`. Its action-line slot `0x3cc` points to `0x4ca8b0`. That function first requires a target or destination. Unless its Force argument is true, it reads the shared countdown (`0xac0178` start frame, `0xac0180` duration) and returns once the duration has elapsed against the current logic frame (`0xa40d2c`). The setter at `0x6d7990` writes the literal duration `0x19`, or 25 frames. Display action handling and control-group selection call that setter. The ordinary selected-unit renderer at `0x6a4fcd` passes Force=false. Planning uses a separate drawing branch; the presence of a Force argument alone does not establish when other interfaces should force persistent lines.

At the project's documented 30-frame reference clock, 25 frames represent 25/30 simulation seconds. The retail clip's roughly 0.77-second observed green line is qualitative confirmation that lines disappear while selection remains; its unknown game-speed setting prevents treating that observation as a separate numeric calibration.

The implementation uses one shared countdown, refreshed by player orders and selection. New commands can therefore temporarily reveal other selected units' existing destinations, rather than assigning an unrelated lifetime to each unit. Pause freezes the countdown and restart clears it. `commandPath` returns authored player goals and queued waypoints, not A* cell nodes; the renderer starts at its interpolated visual position and respects selected ownership, the Target Lines preference, and shroud. The timer does not change orders or movement. All 49 affected candidate simulation, production, facing and geometry checks passed before landing the identical two-file change; both timer and geometry checks passed again in the shared tree. The original 180-second enemy-wave requirement remains unchanged.

The proof establishes ordinary mobile-unit feedback. Full native planning-path rendering and the building-specific rally display still require their own visual comparison. These limits should not be hidden by showing every active order permanently.
